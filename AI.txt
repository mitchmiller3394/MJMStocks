MJMStocks — AI Contribution Log
================================

Purpose
-------
This file tracks AI involvement over time, including:
1) what AI helped produce,
2) an approximate cumulative percentage of AI-generated code/content,
3) what the human author (Mitch) did in each step.

Update Rules
------------
- Append a new entry for every meaningful AI-assisted change.
- Keep entries short, factual, and dated.
- Treat percentages as rough estimates, not exact measurements.
- Re-estimate cumulative AI percentage after major refactors or rewrites.

Scale (for estimates)
---------------------
- 0% = fully human-authored, no AI drafting.
- 50% = mixed authorship, substantial AI drafting + substantial human edits.
- 100% = fully AI-drafted with minimal/no human text/code edits.

Date: 2026-08-10
AI used: GitHub Copilot (Claude Sonnet 4.6)
Summary of AI work:
- Built the Research page (`src/pages/ResearchPage.jsx`) — a market research dashboard showing
  S&P 500 leaderboards with an inline stock detail panel.
  - 8 leaderboards: Highest Price, Largest % Gain, Largest $ Gain, Hot Stocks, Cool Stocks,
    Steadiest Stocks, Trending/Popular, Largest Intraday Range %.
  - Top-5 and Bottom-5 toggle on each board.
  - Inline detail panel: quote KPIs, company profile, 1W/1M/3M performance stats, recent news.
  - Favorites toggle integrated with Portfolio watchlist from within Research.
- Implemented progressive batch loading for the Research snapshot:
  - Processes S&P 500 universe one symbol at a time (1 per ~1,100ms) to respect Finnhub's
    free-tier rate limit of ~60 requests/minute.
  - **Initial full load takes approximately 9–10 minutes** for all ~502 S&P 500 symbols due
    to this rate limiting. This is a known, intentional tradeoff on the free API tier.
  - Snapshot is cached to localStorage (key: `mjmstocks.researchSnapshot.v1`) and reused for
    up to 10 minutes before a manual refresh is allowed.
  - UI shows a progress bar and live status line ("Loading 47/502 — AAPL") during refresh.
  - `onBatch` callback streams partial results to the UI in batches of 5 so boards populate
    progressively rather than waiting for the full load to complete.
  - A 10-minute cooldown prevents accidental rapid re-fetches that would exhaust rate limits.
- Resolved CORS/API issues for the S&P 500 universe:
  - Finnhub `/stock/symbol` endpoint redirects to a static CDN host that blocks browser CORS
    — abandoned.
  - Alpha Vantage `LISTING_STATUS` CSV endpoint also hit CORS in browser context — abandoned.
  - Final solution: hardcoded S&P 500 constituent list (~502 symbols from Wikipedia, Aug 2026)
    in `src/data/sp500Symbols.js`, imported by `finnhubClient.js`. This avoids all runtime
    universe-fetching issues entirely.
- Removed `volume` field from `getQuote()` return value:
  - Finnhub free-tier quote API does not reliably return trading volume.
  - Replaced the "Most Traded (Volume)" leaderboard and KPI tile with "Largest Intraday Range %"
    (computed from `(high - low) / open * 100`), which uses data fields that are available.
- Added Research route and nav link:
  - `/research` route in `App.jsx`, "Research" added to `SiteHeader.jsx` nav.
  - "Research {symbol}" button on `HomePage.jsx` chart panel navigates to Research with
    `?symbol=...` query param to pre-open the inline detail panel.
- Added `src/styles/ResearchPage.css` for Research-specific layout and card styles.
- In-memory `detailCacheRef` (Map) in ResearchPage caches profile/news/stats per symbol for
  the duration of the browser session to minimize repeated API calls when switching symbols.
Known limitations / honest notes:
  - The initial Research page load is **slow by design** on the free Finnhub tier. Users should
    expect ~9–10 minutes for a full S&P 500 snapshot. Subsequent visits within 10 minutes use
    the cached snapshot instantly.
  - The S&P 500 constituent list is hardcoded as of August 2026 and will drift over time as
    index composition changes. It is not dynamically updated.
  - Volume data is not available from the Finnhub free-tier quote endpoint and is not shown
    anywhere in the app.
Rough time spent:
- ~5 hours (Research page build, API debugging, rate-limit architecture, cleanup, documentation).
Human author role:
- Defined all Research page requirements and leaderboard categories.
- Identified CORS failures and rate-limit symptoms, directed the pivot to a hardcoded symbol list.
- Noted that volume data was always empty and requested a replacement metric.
- Approved intraday range % as the replacement.
- Directed cleanup and organizational work (sp500Symbols.js split, volume removal).
- Requested honest documentation of rate-limit slowness.
Entry-level authorship estimate:
- AI authored implementation: ~93%
- Human authored requirements, API constraint identification, and acceptance decisions: ~100%

Date: 2026-08-09
AI used: GitHub Copilot (Claude Sonnet 4.6)
Summary of AI work:
- Refactored AccountPage into focused section components:
  - `BalanceSummarySection`, `DailyFundingSection`, `HoldingsProjectionsSection`, `RecentActivitySection`
  - Organized under `src/components/account/`.
- Refactored PortfolioPage into focused section components:
  - `FavoritesSection`, `OwnedPositionsSection`
  - Organized under `src/components/portfolio/`.
- Extracted `HoldingProjectionCard` into its own standalone component.
- Fixed live gain/loss accuracy across Account and Portfolio owned positions:
  - Both now fetch real current prices via Finnhub API on mount and every 30 seconds.
  - `AccountBalanceBadge` also updated to use live holding prices instead of avg-cost fallback.
  - Account totals (cash + invested at current price) now match the balance badge.
- Improved `estimateAnnualRate()` with new options:
  - Explicit `periodDays` and `timestamps` support for accurate annualization.
  - Optional `stabilize` blending toward a baseline rate for short sample windows.
- Added `estimateHoldingAnnualRate()` for account holding projections:
  - Uses lot purchase dates to compute actual days held.
  - Weights entry price and date by remaining shares (newest lots first).
  - Stabilizes short holding windows against extreme annualized extrapolation.
- Added `estimateChartAnnualRate()` for stock chart projections:
  - Multi-segment momentum detection (blends full-period and segment-level returns).
  - Volatility damping to prevent overconfident projections.
  - Timeframe-aware stabilization mapped to trading days.
- Added `analyzeChartMetrics()` to extract volatility, cycle period, and momentum from chart data.
- Enhanced `buildProjection()` with three modes:
  - `'linear'` (default): Pure compound growth, deterministic, no noise. Used by account projections.
  - `'simple'`: Trend + realistic daily noise based on historical volatility.
  - `'complex'`: Trend + cyclical sine waves (detected cycle period) + momentum phase shifts + noise.
- Added Simple/Complex projection mode toggle to the stock chart UI.
- Fixed account holding projections updating every second (caused by `Math.random()` in `buildProjection` default path — resolved by defaulting to `'linear'` mode).
- Explained projection math and stabilization behavior to the human author in plain English.
Rough time spent:
- ~4 hours (refactor, analytics improvements, bug fixes, validation).
Human author role:
- Identified stale gain/loss values in account badge and Portfolio page.
- Reported per-second re-render bug on Account projections with clear symptom description.
- Guided projection design questions (pattern replication, volatility injection, phase detection, simple vs complex toggle).
- Set acceptance criteria for each projection feature and confirmed when results looked realistic.
- Requested all refactor targets and approved component extraction decisions.
Entry-level authorship estimate:
- AI authored implementation: ~92%
- Human authored requirements, bug reports, and acceptance decisions: ~100%
